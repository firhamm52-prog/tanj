# Checkout TANJ

Jalankan backend dengan Node 24+ (`npm.cmd start` di PowerShell). Live Server/file HTML/GitHub Pages tidak menjalankan transaksi backend.

Untuk mencoba tanpa uang sungguhan, tambahkan `CHECKOUT_DEMO=true` di `.env`, restart server, lalu buka http://localhost:3000. Ongkir berlabel DEMO dan QRIS asli tidak ditampilkan. Pesanan simulasi tidak mengirim WhatsApp. Admin: http://localhost:3000/admin/ → Pesanan & pembayaran. Customer bisa membuka kembali tagihan melalui “Lihat pembayaran terakhir” di tas pada browser yang sama.

Untuk live, gunakan `.env.checkout.example` sebagai referensi variabel dan gabungkan ke `.env` yang sudah ada. Jangan menimpa konfigurasi admin. Pasang QRIS merchant asli di assets; tidak ada QRIS buatan. Uji QRIS merchant mendukung input nominal manual persis hingga satu rupiah. API key disimpan di server. Asal kirim memakai ID hasil pencarian RajaOngkir, bukan kode pos. Berat per produk dalam gram mencakup kemasan; default tidak diasumsikan untuk pembayaran asli. Integrasi saat ini memakai berat rata-rata per unit untuk produk wear; belum termasuk berat per SKU/dimensi. Layanan hanya ditampilkan jika tersedia pada respons provider untuk rute tersebut; tidak menjamin setiap daerah memiliki layanan J&T/JNE.

Alur: detail dan tujuan → quote ongkir berlaku 10 menit → server cek katalog dan reservasi → QRIS dan total → bukti JPG/PNG/WebP maksimal 4 MB → pending_review → admin approve/reject. Total = subtotal + ongkir + penyesuaian 0–999 rupiah agar tiga digit terakhir sama dengan kode unik 001–999. Kode tidak bentrok dengan tagihan awaiting_payment/pending_review/rejected. Tagihan yang belum mengirim bukti kedaluwarsa 24 jam. Bukti pending_review tidak otomatis kedaluwarsa agar transfer yang sudah masuk tetap diperiksa. Bukti ditolak dapat dikirim ulang sebelum batas tagihan. Bukti dan data customer disimpan privat dalam data/orders.sqlite; backup dan kelola masa penyimpanannya saat operasional.

Reservasi stok berada di ledger orders, termasuk approved. Stok katalog saat ini adalah persediaan bruto sebelum pengurangan ledger; jangan kurangi manual lagi untuk transaksi yang sama. Admin/catalog dan storefront belum menampilkan stok tersedia setelah reservasi; checkout melakukan pemeriksaan otoritatif. Pembatalan/refund, pelepasan stok approved, rekonsiliasi dan pengiriman/resi belum memiliki UI dan perlu ditambahkan sebelum operasional penuh.

WhatsApp ditujukan ke nomor customer yang menyetujui notifikasi. Setelah approve, server mencoba mengirim template resmi dengan tiga parameter body berurutan: nama customer, ID pesanan, total dalam rupiah. Buat dan setujui template terlebih dahulu di Meta. Isi versi Graph API yang didukung akun. Status submitted hanya berarti Meta menerima request, bukan pesan sudah sampai; webhook delivery belum diimplementasikan. Jika gagal/belum dikonfigurasi, approval tetap tersimpan dan tombol retry tersedia. Pengiriman otomatis saat approve dan retry manual tersedia; worker antrean retry terjadwal belum ada. Jangan retry saat status sending tanpa rekonsiliasi karena hasil request mungkin tidak diketahui setelah server mati. Notifikasi ke nomor admin terpisah belum dikonfigurasi.

Validasi lokal: `npm.cmd test`. Tes meliputi auth, total server, quote sekali pakai, akses privat bukti, reject/upload ulang/approve, dan larangan approve berulang. Kredensial provider dan QRIS nyata diperlukan untuk pengujian integrasi live.

Referensi: https://rajaongkir.com/docs/shipping-cost/endpoint-rajaongkir-for-search-base/calculate-domestic-cost dan https://www.rajaongkir.com/docs/shipping-cost/getting_started/about

Pada hosting statis, checkout menampilkan status belum tersedia dan menonaktifkan pencarian tujuan, cek ongkir, serta pembayaran. Tidak ada request ke API yang tidak tersedia dan tidak ada tarif perkiraan yang diperlakukan sebagai tarif live. Tautan bantuan admin tetap tersedia. Untuk mengaktifkan transaksi online, frontend dan backend perlu disajikan lewat gateway Node.js dengan konfigurasi provider pada server.
